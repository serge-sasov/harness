# Единые требования к производственному процессу (process.md)

Регламент обязателен для всех ролей harness. Нарушение регламента — блокер задачи.

## 0. Глобальная установка и активация

- Harness устанавливается глобально для пользователя в `~/.config/opencode/`:
  агенты `harness-*`, команды `/harness-*`, skill `harness`, шаблоны и скрипты.
- В проект harness попадает только через `/harness-init`: создаёт
  `harness/process.md`, `harness/version.json`, `harness/templates/`,
  `docs/plan.md`, `docs/activity.puml` и каркас каталогов.
- Активация — только явная. `default_agent` не переключается на harness.
- `harness` primary-агент перед работой проверяет наличие `harness/process.md`
  и `docs/plan.md`; без них работа останавливается с предложением
  выполнить `/harness-init`.
- Глобальные permission-правила запрещают обычным агентам вызывать
  `harness-*` субагентов; это разрешено только primary-агенту `harness`.
- Версия установки фиксируется в `harness/version.json` проекта; `/harness-doctor`
  предупреждает о расхождении с глобальной версией.

| Команда | Назначение |
|---|---|
| `/harness-init` | инициализация harness в текущем проекте |
| `/harness-run T-XXX` | выполнение задачи, приёмка, обновление board, коммит |
| `/harness-board-update all / T-XXX` | синхронизация board, карточек, activity и SVG |
| `/harness-board-report` | read-only сводка по board |
| `/harness-doctor` | проверка глобальной установки и текущего проекта |

## 1. Общие положения

- Harness = роли-под-агенты + общий план выполнения. Все задачи выполняются
  локальными моделями Ollama; внешние API не используются.
- Единственный источник истины по составу работ — `docs/plan.md`.
  Единственный источник истины по правилам процесса — этот файл.
- Каждая задача выполняется ровно одной ролью. Роль не выходит за границы
  своей задачи и своих артефактов.

## 3. План и board

- `docs/plan.md` — board со строками задач. Обязательные колонки:
  `ID | Задача | Роль | Зависимости | Статус | Артефакты | Коммит`.
- `docs/tasks/T-XXX-<slug>.md` — карточка задачи. Обязательные поля:
  `id, title, role, status, depends_on, acceptance, artifacts, blockers, log`.
- Статусы: `pending`, `in_progress`, `blocked`, `done`, `failed`.
- Допустимые переходы: `pending → in_progress → done`; `in_progress → failed`;
  `failed → in_progress` (после исправления); `* → blocked` при внешней блокировке.

## 4. Жизненный цикл задачи

1. Оркестратор проверяет `depends_on`: все предшествующие задачи — `done`.
2. Статус задачи → `in_progress` (plan.md, карточка, диаграмма).
3. Роль выполняет задачу строго по `acceptance` из карточки.
4. Приёмка: проверка критериев; при провале — `failed` (п. 7).
5. Статус → `done`, запись в `log`: что сделано, файлы, команды, результаты.

## 5. Обновление артефактов после каждой задачи (обязательный порядок)

1. `docs/plan.md` — обновить строку задачи (статус, артефакты, хэш коммита).
2. `docs/tasks/T-XXX-<slug>.md` — статус, лог, блокеры.
3. `docs/activity.puml` — цвет блока задачи:
   - `done` — зелёный `#90EE90`
   - `pending` — серый `#D3D3D3`
   - `in_progress` — жёлтый `#FFE082`
   - `failed` — красный `#FF9090`
   - `blocked` — оранжевый `#FFB347`
4. Перерендер `docs/activity.svg` через MCP `plantuml-render`.
5. `git commit` (п. 6).

## 6. Git-дисциплина

- Репозиторий — в корне проекта. Ветка по умолчанию — `master`.
- Коммит после каждой значимой задачи; минимум — один коммит на задачу.
- Формат сообщения: `T-XXX: краткое описание` (для служебных — `chore: ...`).
- Запрещено: `git push`, `git tag`, коммит секретов и `.env`, правка истории.
- В коммит включать только файлы задачи; посторонние изменения — отдельным коммитом.

## 7. Обработка ошибок

- Любой провал приёмки → статус `failed`, блок в карточке: что упало, вывод, гипотеза.
- Зависимые задачи не стартуют, пока задача не переведена в `done`.
- Максимум 3 попытки исправления на задачу; далее — `blocked` и эскалация пользователю.
- Причина ошибки фиксируется в логе карточки, не удаляется при исправлении.

## 8. Артефакты ролей

| Роль | Куда пишет |
|---|---|
| harness (primary lead) | не пишет файлы; читает board/карточки и маршрутизирует роли |
| orchestrator | `docs/plan.md`, `docs/tasks/`, `docs/activity.puml`, README |
| analyst | `docs/analysis/` (требования, вопросы, глоссарий) |

| qa | `docs/qa/` (отчёты ревью, результаты прогонов) |
| doc-writer | `docs/guides/`, `README.md`, финализация ADR |

## 9. Запреты

- Правка `~/.config/opencode/**` и системных конфигов.
- Prod-действия: `git push`, `docker push`, деплой вне local/staging, миграции prod-данных.
- Секреты, токены, ключи в коде, логах, коммитах.
- Вложенный вызов под-агентов (`task: deny` у ролевых sub-agent'ов; primary `harness` имеет task allow только для harness-ролей).
- Выход за пределы диска `C:` (см. permissions агентов).
