---
description: "Обновление плана, карточки и activity-диаграммы по текущему статусу задачи"
---

Обнови артефакты планирования по регламенту `harness/process.md` п. 5.

Вход: `$ARGUMENTS` — ID задачи (например, `T-007`) или `all` для полной сверки.

1. Прочитай `docs/plan.md`, все карточки `docs/tasks/T-*.md` и `docs/activity.puml`.
2. Для указанной задачи (или всех) приведи статусы к фактическому состоянию:
   - `done` — зелёный `#90EE90`;
   - `in_progress` — жёлтый `#FFE082`;
   - `pending` — серый `#D3D3D3`;
   - `failed` — красный `#FF9090`;
   - `blocked` — оранжевый `#FFB347`.
3. Сверь статусы карточек и `docs/plan.md`; при расхождении — статус из карточки
   считается истинным, план подстраивается.
4. Заполни колонку `Коммит` фактическими хэшами из `git log --oneline`
   (задачи, у которых коммит уже существует).
5. Перерендери `docs/activity.svg` через MCP `plantuml-render` (`render_file`).
6. Проверь `check_syntax` исходника до рендера; при ошибке — стоп, отчёт.
7. Коммит: `chore: board update ($ARGUMENTS)`.

Отчёт: какие статусы изменены, какие коммиты записаны, путь к SVG.
