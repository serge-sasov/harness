description: "Запуск задачи T-XXX ролевым sub-agent'ом по регламенту harness/process.md"
---

Выполни задачу `$ARGUMENTS` по регламенту `harness/process.md`.

Алгоритм:

1. Прочитай `docs/plan.md` и карточку `docs/tasks/$ARGUMENTS-*.md`.
2. Проверь `depends_on`: все предшествующие задачи должны быть `done`.
   Если нет — стоп, отчёт о блокировке, статус зависимой не менять.
3. Переведи задачу в `in_progress`: строка в `docs/plan.md`, карточка, цвет
   `#FFE082` в `docs/activity.puml`, перерендер `docs/activity.svg` через
   MCP `plantuml-render`.
4. Определи роль из карточки и вызови соответствующего sub-agent через `task`
   с `subagent_type`: `analyst` | `architect` | `coder` | `qa` | `doc-writer`
   | `orchestrator`. В промпте передай: ID задачи, путь к карточке, критерии
   `acceptance`, ссылки на входные артефакты, требования регламента пп. 4–7.
5. Прими результат по `acceptance`. При успехе — `done`; при провале —
   `failed` с записью причины в карточку (блок Try/Failed в Log).
6. Обнови `docs/plan.md`, карточку, `docs/activity.puml` (зелёный/красный),
   перерендери `docs/activity.svg`.
7. Сделай коммит: `git add` только затронутых файлов, сообщение `T-XXX: ...`.
8. Отчёт: статус, коммит, разблокированные задачи, блокеры.

Ограничения: максимум 3 попытки на задачу; далее `blocked` и эскалация
пользователю. Не переписывай историю git.
