## Scope

The chunk ledger and its tooling, as required by ADR-006 (T-037):

- `harness/scripts/chunk-validate.py` - deterministic ledger validation.
- `harness/scripts/chunk.ps1` - ledger management actions.
- `harness/templates/chunk-ledger.md` - schema, state machine, brief contract.
- `harness/scripts/stage-done.ps1` - `-Chunk`, the stage gate, produced files in
  the evidence ledger, `## Chunks` in the checkpoint.
- `harness/scripts/harness-lib.ps1` - `Get-SessionUsage`, `Get-ChunkUsage`.
- `harness/scripts/measure-tokens.ps1` - `-ByChunk`.
- `harness/scripts/init.ps1` - creates `docs/chunks/` in a new project.

## Artifacts

- `chunk-validate.py`: schema, task/file identity, unique ids, parent links,
  depth `1..3`, state enum, role/stage inheritance from the parent, ancestor-safe
  exclusive `owns`, produced-inside-owns, sha256 match, top-level coverage of the
  card artifacts, role write areas, blocked-has-issue. Error codes are stable
  (`E_*`), warnings are `W_*`, `--json` and `--no-hash` are supported.
- `chunk.ps1`: `init`, `add`, `plan` (plan file merge), `claim`, `complete`
  (hashes every produced file, refuses a missing file), `fail` (`-Blocked` needs
  `-Issue`), `list`, `show`, `status`, `usage` (merges per-chunk usage from the
  session database), `verify` (delegates to the validator).
- `chunk-ledger.md`: full field tables, state machine, depth and ownership rules,
  a filled example, and the brief template.
- `stage-done.ps1`: validates the ledger before anything else, refuses to close a
  checkpoint while a chunk of the stage is not `done` (bypass with `-Force`),
  adds the chunk produced files to the hashed artifacts, and records the
  `## Chunks` table in the checkpoint.
- `measure-tokens.ps1 -ByChunk`: attributes sessions to `T-XXX` and to the chunk
  id from the session title (`T-008.C5b`), with console, Markdown, and JSON
  output.

## Verification

- `python harness/scripts/chunk-validate.py --self-test` -> 12 cases, 0
  failures: valid, owns overlap, produced outside owns, hash mismatch, coverage
  gap, bad state, bad depth, role area, parent inheritance, blocked without
  issue, valid deep child, invalid JSON.
- Sandbox run (`Temp\opencode\chunk-test`, task T-900): `init` -> `add` ->
  `claim` -> `complete` -> `status` -> `verify` produced a valid ledger with a
  recorded sha256; `add -Parent` created a `d2` chunk; `fail` recorded a note.
- Sandbox run (`Temp\opencode\stage-test`): `stage-done.ps1 -Task T-900
  -Checkpoint CP-1` refused with `chunks not done for stage I-01: C1=failed`;
  after `complete` the same call produced the checkpoint with the `## Chunks`
  table and the produced file counted by `artifacts-exist`.
- `measure-tokens.ps1 -ByChunk -ProjectPath ai-task-tracker -Task T-008` returned
  `T-008 ~ sessions=40 in=4137789 out=827751 ratio=10x` (the pre-3.0.0 sessions
  carry no chunk id yet, so they aggregate under `~`).
- Parser check: all five changed PowerShell scripts parse without errors;
  `chunk-validate.py` compiles under Python 3.12.
